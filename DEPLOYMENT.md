# MerebHub Licensing Backend Deployment Guide

This repository is now split into two deployment paths:

- `docker-compose.yml` — current local development stack, including old local WordPress services.
- `docker-compose.backend.yml` — backend-only licensing stack for VPS/Docker hosts.
- `render.yaml` — Render Blueprint for managed Postgres, managed Key Value/Redis, Keygen API, Keygen worker, and FastAPI middleware.

Do not deploy the local WordPress/MariaDB/certbot services when WordPress is hosted separately.

## Public URLs

Use public HTTPS URLs everywhere outside Docker:

- Desktop app `activation.config`: `baseUrl=https://license-api.merebhub.com`
- Hosted WordPress Chapa/Keygen plugin middleware URL: `https://license-api.merebhub.com`
- Middleware `WOOCOMMERCE_URL`: `https://merebhub.com`
- Chapa callback URL: `https://merebhub.com/wc-api/wc_gateway_chapa`

Never use these in production:

- `http://127.0.0.1:8000`
- `http://localhost:8000`
- local `.test` development domains
- Docker-only hostnames from WordPress, such as `http://middleware-api:8000`

## Render deployment

1. Push the backend repo to GitHub/GitLab.
2. In Render, create a new Blueprint from `render.yaml`.
3. Fill all `sync: false` values in the Render dashboard.
4. Use managed Render Postgres and Render Key Value from the Blueprint.
5. Confirm services deploy in this order:
   - `merebhub-keygen-db`
   - `merebhub-keygen-redis`
   - `merebhub-keygen-api`
   - `merebhub-keygen-worker`
   - `merebhub-middleware-api`
6. Check health:
   - Middleware: `https://<middleware-domain>/health`
   - Keygen API from internal/private service logs or shell: `/v1/health`
7. Configure your hosted WordPress plugins to call the public middleware domain.
8. Rebuild the desktop demo app with the same public middleware domain in `activation.config`.

## Required Render secret values

Set these manually in Render when prompted:

- `KEYGEN_HOST` — the Keygen API domain/host.
- `KEYGEN_HOSTS` — comma-separated allowed Keygen hosts.
- `KEYGEN_ACCOUNT_ID` — Keygen account UUID used by the middleware and policies.
- `KEYGEN_ADMIN_EMAIL`
- `KEYGEN_ADMIN_PASSWORD`
- `KEYGEN_ADMIN_TOKEN`
- `WOOCOMMERCE_URL`
- `WOOCOMMERCE_CONSUMER_KEY`
- `WOOCOMMERCE_CONSUMER_SECRET`
- Chapa keys if the middleware uses them directly.

`SECRET_KEY_BASE` and Keygen encryption keys are generated by Render for the Keygen API and shared into the worker.

## Backend-only Docker deployment

For a VPS or other Docker host:

```bash
cp .env.production.example .env.production
# edit .env.production with real values, never commit it
docker compose -f docker-compose.backend.yml --env-file .env.production config --quiet
docker compose -f docker-compose.backend.yml --env-file .env.production up -d --build
```

Run Keygen setup/migrations before first real use. Locally this was:

```bash
docker compose -f docker-compose.backend.yml --env-file .env.production run --rm keygen-api setup
```

If the image/entrypoint does not support `setup` on the target host, run the Keygen CE equivalent migration/setup command from the Keygen docs/image version you deploy.

## Desktop app rebuild

Edit:

```text
C:\Users\user\Documents\Apps\windows-demo-apps\demo-app-2-clock\activation.config
```

Set:

```ini
baseUrl=https://license-api.merebhub.com
```

Then from:

```text
C:\Users\user\Documents\Apps\windows-demo-apps
```

run:

```bash
'/c/Users/user/.dotnet-sdk/dotnet.exe' publish demo-app-2-clock/DemoApp2.ClockViewer.csproj \
  -c Release \
  -f net8.0-windows \
  -r win-x64 \
  --self-contained true \
  /p:PublishSingleFile=true \
  /p:EnableCompressionInSingleFile=true \
  -o dist/licensed-demo-clock-public-win-x64
```

## QR activation requirements

QR activation only works when the QR contains a public HTTPS URL reachable from a phone. Local-only URLs will not work.

Good:

```text
https://license-api.merebhub.com/...
```

Bad:

```text
http://127.0.0.1:8000/...
http://localhost:8000/...
local `.test` development URLs
```

Also make sure QR payloads do not contain admin tokens, database URLs, or Chapa secrets.

## Production cautions

- Do not expose database or Redis publicly.
- Use paid always-on services for licensing; free cold starts can cause activation timeouts.
- Keep Keygen API private if the desktop app only needs middleware.
- Rotate any secret that was ever committed or pasted into a command.
- Use hosted WordPress REST API keys with Read/Write permissions.
- Keep the WordPress thank-you page privacy-safe: no license key, no activate button, no download button.
- Back up Render Postgres regularly.
- Test order purchase → license provisioning → app activation → machine count before real launch.
